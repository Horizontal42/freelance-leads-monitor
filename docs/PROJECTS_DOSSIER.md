## 1. Speech Analytics (Intervesp) - Коммерческий B2B проект (NDA)
- **Роль:** Полная разработка под ключ (архитектура, бэкенд, ML-пайплайн, интеграция).
- **Стек:** Python 3.12, FastAPI, Celery, Redis, PostgreSQL, Alembic, Docker, WhisperX (`large-v3-turbo`), pyannote, Ollama/LM Studio (Qwen 32B), Bitrix24 REST API, MinIO (S3), Weasyprint, Jinja2, pytest (~480 тестов).
- **Что делает:** Автоматическая оценка звонков отдела продаж и аудит ведения сделок в Битрикс24. Битрикс присылает вебхук завершения звонка -> Celery скачивает MP3 из телефонии -> WhisperX делает транскрибацию и диаризацию (менеджер/клиент) -> LLM оценивает разговор по рубрикатору -> результаты, саммари и рекомендации пишутся обратно в карточку сделки Битрикс24 и генерируется накопительный PDF-отчет в S3.
- **Сложные инженерные решения (Пруфы для откликов):**
  1. **Детерминированная валидация оценок и цитат:** Исключен разброс оценок нейросети при повторном анализе одного и того же звонка: LLM извлекает цитаты, а итоговый балл пересчитывается кодом с fuzzy-проверкой цитат по транскрипту (`difflib.SequenceMatcher`, порог совпадения 0.8). Результат воспроизводим на 100%.
  2. **Раздельные очереди Celery (IO vs GPU с батчингом):** Очередь `prepare` (быстрый I/O, скачивание, concurrency > 1) и очередь `gpu` (Whisper + LLM, concurrency = 1). Звонки копятся в очереди, пока GPU занят, и обрабатываются динамическими пачками (`batch_size=3`).
  3. **Оптимизация работы с GPU и оперативной памятью:** Настроено принудительное освобождение системной памяти после выгрузки тяжелых ML-моделей на уровне аллокатора ОС (C-библиотек) и разделение воркеров на IO-bound и GPU-bound очереди.
  4. **Накопительный PDF-отчет O(n):** Генерация сводного PDF по всем звонкам сделки. Каждый звонок хэшируется по SHA1 от JSON-полей. При добавлении звонка рендерятся только новые блоки, а не пересчитывается вся история.
  5. **Детекция автоответчиков / пустых звонков (Voicemail gate):** Фильтрация звонков по количеству реальных слов именно клиента, исключая лишние вызовы LLM и записи в БД.
- **Для каких откликов использовать:** Транскрибация звонков, речевая аналитика, интеграция Битрикс24/CRM, локальные нейросети (Whisper, Ollama) на сервере заказчика, Celery-пайплайны, генерация PDF-отчетов.

## 2. Avia_Pars — Telegram-бот мониторинга цен (Pet-проект)
- **Роль:** Автор и единственный разработчик.
- **Стек:** Python 3.12, asyncio, aiogram 3, SQLite (WAL-режим), pydantic-settings, mypy (strict), `curl_cffi`, `patchright` (Chromium), pytest (208 тестов, записанные fixtures реальных ответов).
- **Что делает:** Мониторинг авиа- и жд-билетов по сложным маршрутам с гибкими датами и уведомлением в Telegram при падении цены ниже порога. Работает на слабой VDS (1 vCPU, 1 GB RAM).
- **Сложные инженерные решения (Пруфы для откликов):**
  1. **Обход сложных антибот-систем двух типов:**
     - *S7 (ServicePipe JS-челлендж):* TLS-имперсонация через `curl_cffi` + закэшированные cookies от браузерного солвера. Если прилетает сложный JS-челлендж — вызывается `patchright` в отдельном изолированном процессе (`subprocess`). Изоляция процесса защищает память основного бота от жора ресурсов Chromium (300–400 МБ освобождаются сразу после решения).
     - *Победа (WAF датацентровых IP):* Блокирует любые датацентровые и VPN IP по автономным системам (ASN). Решено пробросом запросов через домашний residential Tailscale SOCKS5-релей.
  2. **Поиск составных маршрутов через хабы:** Комбинатор сам ищет рейсы с пересадкой и сравнивает их по суммарной цене с прямыми. Хаб ранжируется по геометрии через формулу гаверсинуса (расчет крюка `detour_km`), а не просто по популярности городов.
  3. **UX «Один экран на чат» (`screen.py`):** Вместо спама десятками сообщений мастер добавления маршрута и поиска динамически редактирует одно сообщение через якорь `(chat_id, message_id)` в FSM, корректно обрабатывая ошибки `message is not modified`.
  4. **Circuit Breaker и Rate Limiter на каждый источник:** Защита от банов: при серии ошибок адаптер источника временно отключается, запросы к внешним сайтам строго лимитируются семафорами.
- **Для каких откликов использовать:** Telegram-боты любой сложности, парсинг защищенных сайтов (Cloudflare, ServicePipe, WAF), обход блокировок, автоматизация поиска билетов/товаров, асинхронные пайплайны.

## 3. netsleuth / netcheck — Кроссплатформенный CLI сетевой диагностики
- **Роль:** Автор и единственный разработчик (Open-Source на GitHub: `Horizontal42/netsleuth`, 1★).
- **Стек:** Python 3.14+, Typer, Rich, httpx, dnspython, psutil, ctypes, struct, pytest (44 файла, 857 тестов).
- **Что делает:** Глубокая сетевая диагностика хоста: определение реального провайдера, детекция VPN/прокси, утечки DNS на каждом интерфейсе, BGP-маршруты, каскадный замер скорости и bufferbloat.
- **Сложные инженерные решения (Пруфы для откликов):**
  1. **Пинг и трассировка под Windows БЕЗ прав администратора:** Вместо raw-сокетов, требующих админки, реализована прямая обвязка над нативной Windows DLL `Iphlpapi.dll` (`IcmpSendEcho2`) через `ctypes`. Корректно учтено 64-битное выравнивание структур памяти и хэндлов под разные архитектуры.
  2. **Корректная обработка OEM-кодировок Windows:** Динамическое определение кодовой страницы через `GetOEMCP()` (решена проблема падения парсеров на русской Windows с выводом `cp866`).
  3. **Прозрачный скоринг VPN:** Взвешенная линейная модель (анализ MTU, несовпадение таймзон, Cloudflare WARP, DNS ASN mismatch, tunnel-интерфейсы).
- **Для каких откликов использовать:** Системные скрипты, CLI-утилиты, сетевые задачи, парсинг системного вывода, ctypes / интеграция с Win32 API, написание надежного кода с высоким покрытием тестами.

## 4. summarum / Numi — Калькулятор-блокнот с NLP-парсером
- **Роль:** Автор и единственный разработчик (Open-Source на GitHub: `Horizontal42/summarum`, 1★).
- **Стек:** Tauri 2 (Rust), TypeScript, CodeMirror 6, `decimal.js`, Vitest (259 тестов).
- **Что делает:** Десктопный калькулятор под Windows/macOS/Linux: текст преобразуется в живые вычисления на лету (конвертация единиц, валюты, крипта, даты, проценты).
- **Сложные инженерные решения (Пруфы для откликов):**
  1. **Pratt-парсер с фильтрацией естественного языка:** Двухуровневое шумоподавление — лексический слой отсеивает обычные слова, синтаксический слой проверяет контекст операторов (например, "spent 20 on pizza and 5 on coffee" преобразуется в `20 + 5`).
  2. **Безопасность файловых операций на Rust:** Модуль `DataDirGate` с жесткой валидацией путей перед допуском UI к чтению диска.
  3. **Точная десятеричная арифметика:** Полное исключение артефактов `IEEE 754 float` через `decimal.js`.
- **Для каких откликов использовать:** Десктопные приложения на Tauri/Rust/Electron, парсеры текста и формул, TypeScript/Frontend задачи со сложной логикой.

## 8. RAG-ассистент по сложной номенклатуре + LLM-скоринг звонков (B2B)
- **Роль:** Совместная разработка с коллегой (архитектура, векторный поиск, интеграция).
- **Стек:** Python 3.11+, LangChain, Qdrant (векторная СУБД), OpenAI API / LLM, WhisperX, FastAPI, Docker.
- **О клиенте и проблеме:** Крупная производственная B2B-компания (отдел продаж 130+ менеджеров). Менеджеры теряли заявки из-за огромного каталога и медленного поиска данных по ГОСТам, спецификациям и прайсам во время звонка. Контроль качества звонков охватывал менее 5% разговоров.
- **Что сделано:**
  1. **RAG-система на базе LangChain и Qdrant:** Индексация сложной документации, таблиц прайсов и ГОСТов в векторной базе Qdrant. Бот выдает точные подсказки и фрагменты документов за секунды прямо в процессе переговоров.
  2. **Потоковый скоринг звонков:** Микросервис на FastAPI для расшифровки через WhisperX и оценки диалогов через LLM (проверка скрипта, фиксация договоренностей, отработка возражений, генерация саммари).
- **Результат:** 100% звонков охвачены автоматическим анализом, сокращение времени подготовки ответов клиенту в разы.
- **Для каких откликов использовать:** Корпоративные RAG-системы, умный поиск по PDF/документам, векторные базы (Qdrant/Chroma/Pinecone), корпоративные базы знаний, боты-ассистенты для сотрудников.

## 9. Компьютерное зрение и видеоаналитика детекции аномалий (AgroTech)
- **Проекты в архивах:** `bos-vision` (идентификация) и `calving-monitor` (мониторинг видеопотоков).
- **Роль:** Разработка ML/CV пайплайнов и бэкенда с коллегой.
- **Стек:** Python, YOLOv8, YOLOv11m-cls, ByteTrack, EfficientNet-B1 (Re-ID), IsolationForest, OpenCV, CUDA (GPU-инференс), FastAPI, Docker.
- **О клиенте и проблеме:** Крупное предприятие в сфере AgroTech (животноводство). Круглосуточный мониторинг производственных зон и загонов с беременными животными велся операторами через камеры. Из-за человеческого фактора и усталости пропускались критические события (отелы, травмы), что вело к прямым финансовым потерям.
- **Что сделано:**
  1. **Многокамерный RTSP-пайплайн (`calving-monitor`):** Потоковая обработка видео с IP-камер на 1 FPS. Цепочка: `RtspReader` $\to$ Детекция животных (YOLOv8) $\to$ Трекинг объектов между кадрами (ByteTrack) $\to$ Классификация позы (YOLOv11m-cls) $\to$ Извлечение временных признаков в скользящем окне 5 минут $\to$ Детекция аномального поведения (`IsolationForest`) $\to$ Детекция признаков события $\to$ Менеджер алертов с FSM-машиной состояний (NORMAL $\to$ WATCH $\to$ ALERT $\to$ CONFIRMED).
  2. **Система биометрической идентификации (`bos-vision`):** Двухстадийный пайплайн: сегментация животного моделью YOLOv8 + извлечение уникального цифрового отпечатка (эмбеддинга) через EfficientNet-B1 с поиском совпадения по галерее. API на FastAPI с JWT-авторизацией.
- **Результат:** Автоматический круглосуточный мониторинг без участия человека, реакция на инциденты за доли секунды.
- **Для каких откликов использовать:** Компьютерное зрение (Computer Vision), детекция объектов и аномалий, видеоаналитика с IP-камер / RTSP, трекинг (ByteTrack), fine-tuning YOLO, локальный CUDA/GPU инференс, микросервисы обработки медиа.
